# Threat Model: Mosaera Lite repo agent (first vertical slice)

- Status: current
- Owner: Alejandro Rengifo
- Last reviewed: 2026-07 (kept current with each run-gate / trust-boundary arc — see the ADR-linked rows)
- Next review trigger: a new external entry point, a new trust boundary, or an auth/sandbox change

## Scope

The CLI-driven PM → Coder → Reviewer loop operating on a cloned repository:
`packages/core` (model gateway, sandbox, repo tools, orchestrator, CLI),
`packages/agents`, `packages/policies`. **The API/web server surface** (login, sessions,
admin gate, config-in-UI writes, transcript API) is covered separately by **TM-0002**.

## Assets

- **The target/source repository** — never modified by agents, with one explicit,
  double-gated exception: the opt-in `delete_file` tool (admin toggle **and** per-action
  human approval; off by default — see the delete-tool feature). Blast radius is bounded to
  files inside the workspace clone.
- **The host filesystem** outside `.mosaera/workspaces/` — must be unreachable
  from agent tools and sandboxed test runs.
- **The evidence store (`.mosaera/`)** — the benchmark scorecard corpus, run checkpoints,
  `settings.json` (which holds provider API keys in plaintext), and the agents' own workspaces.
  Every governance claim this project makes rests on it, and it is **the parent directory of the
  sandbox's writable area**, not a sibling: the isolation boundary lives inside the thing the rest
  of the system is protecting. Committed regression baselines
  (`packages/core/mosaera_core/bench/baselines/`) are the one part held in git and therefore the one
  part that survives its loss.
- **Model context** — no secrets (`.env`, credentials) may enter prompts.
- **The Mosaera repo's own governance surfaces** (`AGENTS.md`, policies, CI) —
  when Mosaera works on a clone of itself, these are high-value targets.
- **BYOM provider API keys** (#21) — user-supplied hosted-provider credentials,
  stored server-side; must be write-only over the API and never logged/echoed.
- Integrity of delivery reports and run audit trail.
- **The durable project map** (#40, ADR-0047) — a persisted, UNTRUSTED, repo-derived view of a
  project (`project_map_dimensions` + `project_map_observations` in `memory`). Steers every future
  run, so its integrity is a persistent-compromise target — see the new threat row below. The
  **project charter** (`project_charters`) is its trusted counterpart (operator intent + posture),
  and the two must never be confused.

## Actors

- **User** (trusted): supplies task + repo, answers the approval gate.
- **Mosaera agents** (semi-trusted executors): local LLMs following prompts; may
  hallucinate or be steered by injected instructions.
- **Untrusted repo content** (attacker channel): source files, READMEs, test
  fixtures, issue text in the cloned repo may contain prompt-injection payloads.
- **Test code executed in the sandbox** (attacker code-execution channel).

## Architecture and trust boundaries

1. CLI (user intent) → orchestrator (LangGraph) — trusted.
2. Orchestrator → model provider (`get_chat_model`) — Ollama on the local hop by
   default; **optionally** a user-configured hosted provider per role (BYOM #21),
   which sends model context off-box. Local by default; remote is explicit opt-in.
3. Agent → repo tools → **workspace clone** — writes confined by path guard.
4. Tools → **SandboxWorker** subprocess — cwd-restricted, env-scrubbed, timed out,
   best-effort network isolation (`unshare -rn` where available).
5. Workspace clone ↔ source repo — one-way at clone time only.

## Entry points

- `mosaera run` CLI (task string, repo path/URL, flags).
- Cloned repo content read into model context.
- Test commands executed in the sandbox — including an OPERATOR-SUPPLIED command (`projects.test_cmd`, ADR-0113), which was CLI-only (`--test-cmd`) before 2026-08-24.

## Security controls

Deny-by-default tool allowlist (`packages/policies/allowlist.py`); human approval
gate (`packages/policies/approval.py`, LangGraph `interrupt`); path-escape guard
(`mosaera_core/tools/repo.py`); Docker container isolation for test execution
(`mosaera_core/sandbox.py` `DockerSandbox`, `infra/docker/sandbox.Dockerfile`) with a
subprocess fallback; run branch + delivery report as audit artifact; CODEOWNERS on all
steering surfaces.

  deny-by-default (run in CI).

  the container; the install phase (`run_setup`) asserts egress is allowed.
